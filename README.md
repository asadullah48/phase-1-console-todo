# Phase I: In-Memory Python Console Todo Application

## 🎯 Overview

A production-grade, spec-driven Python console application for Todo management built using Clean Architecture principles. This application serves as the foundation for evolution through 5 phases of the Panaversity Hackathon II.

## 🏗️ Architecture

### Design Patterns
- **Repository Pattern**: Abstracts storage for easy migration to databases
- **Service Layer**: Encapsulates business logic for API exposure
- **Dependency Injection**: Loose coupling for testability
- **Domain-Driven Design**: Rich domain models with validation

## ✨ Features

### Core Features
- ✅ Add tasks with title, description, priority, tags, due dates
- ✅ View all tasks with formatted display
- ✅ Update task fields
- ✅ Delete tasks with confirmation
- ✅ Mark tasks complete/incomplete

### Advanced Features
- ✅ **Priorities**: LOW, MEDIUM, HIGH, URGENT with visual indicators
- ✅ **Tags**: Multiple tags per task for categorization
- ✅ **Search & Filter**: By title, tag, status, priority
- ✅ **Sorting**: By priority, due date, created date, status
- ✅ **Due Dates**: ISO 8601 format with overdue detection
- ✅ **Recurring Tasks**: Daily, weekly, monthly auto-generation

## 🔧 Technical Details

### Requirements
- Python 3.11+
- No external dependencies (standard library only)

### Data Models

**Task Entity**
```python
- id: str (UUID4)
- title: str (1-200 chars, required)
- description: str (0-1000 chars)
- status: TaskStatus (PENDING | COMPLETED)
- priority: Priority (LOW | MEDIUM | HIGH | URGENT)
- tags: List[str]
- due_date: Optional[datetime]
- created_at: datetime
- updated_at: datetime
- completed_at: Optional[datetime]
- recurrence: Optional[Recurrence] (DAILY | WEEKLY | MONTHLY)
```

### Validation Rules
- Title: Required, 1-200 characters
- Description: Optional, max 1000 characters
- Due dates: Must be present or future
- Tags: Auto-normalized (trimmed, lowercase)
- Priorities: Enum-validated
- Recurring tasks: Auto-create next instance on completion
